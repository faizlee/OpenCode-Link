## 一、产品结构

OpenCodex Link 采用三个清晰的执行面：

1. Windows 轻量托盘控制器：后台服务生命周期的唯一用户入口。
2. 默认浏览器中的电脑管理台：扫码、设备、连接、设置和状态查看。
3. 手机网页/PWA：查看 Codex 任务、发送消息和附件、读取回答。

托盘不承载完整管理界面。用户点击“打开 OpenCodex Link”后进入本机浏览器管理台；关闭浏览器不等于停止后台服务。

## 二、职责边界

### Windows 托盘

- 显示运行中、已停止、更新中和异常状态。
- 打开电脑管理台。
- 启动、停止和重启后台服务。
- 显示托盘版本与当前服务版本。
- 安装或启动新版时识别并正常关闭属于 OpenCodex Link 的旧服务，等待端口释放后再启动新版。
- 端口被其他软件占用时明确报错，不得按端口号直接结束未知进程。
- 提供开机启动、日志和退出入口；退出时明确说明是否同时停止服务。

### 电脑浏览器管理台

- 展示服务、Codex、局域网、版本和设备状态。
- 添加手机并生成短时二维码。
- 管理受信任设备。
- 展示固定名称、IP 备用入口与 Tailscale 直连入口的真实可用状态。
- 提供非破坏性的日常设置。
- 停止服务、替换版本等动作必须交给托盘控制器执行，网页不能冒充服务 Owner。

### 手机网页/PWA

- 保持现有任务选择、消息、附件和回答体验。
- 不增加服务安装、版本管理和电脑诊断职责。

## 三、电脑管理台信息架构

### 1. 概览

- 顶部显示 OpenCodex Link、运行状态和当前版本。
- 首屏只保留服务状态、Codex 连接、设备数量、固定地址状态与主要异常。
- 主操作是“添加手机”；次操作是“复制访问地址”。
- 展示最近使用的少量设备，完整列表进入设备页。
- 若托盘版本与服务版本不一致，显示明确警告和“交给托盘切换版本”的操作。

### 2. 设备

- 显示设备名称、类型、最近使用时间、首次添加时间和授权状态。
- 在能够可靠判断时标记“当前设备”，不能可靠判断时不得猜测。
- 支持改名、单独解除、勾选后批量清理。
- 长期未使用设备默认折叠，但不得自动删除。
- 默认名称优先直接显示浏览器可靠提供的手机型号。Android 优先读取 Client Hint 型号，其次读取 User-Agent 中 `Build/` 前的型号；拿不到可信型号时只回退为 Android 手机、iPhone、iPad 或桌面浏览器等可证明类型，不猜具体机型。
- 已有 Android 手机等泛化名称在同一受信任设备下次访问时可以升级为型号；用户手动改名后不得自动覆盖。型号只用于显示，不作为同一设备判断或自动合并依据。

### 3. 连接

- 分别显示固定名称、当前局域网地址、Tailscale 地址和实际推荐入口。
- 固定名称不可用时明确说明正在使用 IP 备用入口。
- 提供复制地址和重新检测。
- 网卡、端口、mDNS 等技术信息默认折叠。

### 4. 设置

- 开机自动启动。
- 启动后是否自动打开管理台。
- 浏览器关闭后是否保持后台服务。
- 附件临时文件与清理说明。
- 需要服务生命周期变化的设置必须由托盘确认并执行。

### 5. 关于

- 托盘版本、服务版本、构建标识与最近启动时间。
- 日志入口、数据目录和许可证信息。
- 当前版本与更新包不一致时给出普通用户能理解的说明。

## 四、添加手机流程

二维码不长期占据概览页。用户点击“添加手机”后打开独立面板：

- 只显示一个“绑定这台手机与电脑”的二维码、剩余有效时间和刷新按钮；不得让用户选择局域网、固定名称或 Tailscale。
- 用户始终从电脑端“添加手机”进入；唯一二维码先保证当前局域网可扫码，配对后再由页面后台探测并迁移到可用的 Tailscale 等路径，不要求用户查找或手工打开技术地址。
- 软件根据可达性自动选择扫码入口，并在已绑定后无感切换连接路径；所有技术地址、候选状态与备用入口收进折叠详情。
- 扫码是唯一授权入口，未配对设备不显示密码输入框，只说明如何回到电脑管理台扫码。
- 同一受信任浏览器重复扫码只刷新原设备记录。
- 首次配对后在 IP、固定名称、Tailscale 或后续其他可达地址之间切换时沿用同一设备身份，不要求重新扫码或重新登录。
- 配对页面自动逐个登记当前可达来源并返回原页面；登记完成后，用户直接打开其中任一原始链接都必须识别为同一设备，不依赖再次附加二维码参数。
- Tailscale 入口不加入 `.local` 的物理局域网广播；手机未连接 Tailnet 时继续停留在已可用入口。
- 二维码过期、设备已解除或浏览器数据已清理时，明确说明需要重新配对。

### 迁移到管理台的规则

- 主背景使用暖白纸面 `#fffcf8`，主文字使用近黑 `#1b1b1b`。
- 信号红 `#e7131a` 用于品牌强调、选中态和关键操作，但错误与破坏性动作必须同时使用文字或图标说明。
- 一级标题采用编辑感中文衬线字体栈；正文、标签、按钮和数据使用中性无衬线字体栈。
- 使用 `4 / 8 / 12 / 16 / 24 / 32 / 48` 的基础间距节奏。
- 表面保持平整，使用 `1px` 细线和留白建立层级，不使用装饰阴影。
- 页面采用清晰分区、行式设备信息和克制的状态标签，不使用大量悬浮卡片组成的仪表盘矩阵。
- 桌面端优先保证管理效率；窄屏保证不横向溢出、主要操作可达和状态可读，不强行复制文章的窄栏连续阅读结构。

### 禁止项

- 不复制 TIME Logo、刊名、红色封面框、原文章图片、专有字体或第三方品牌资产。
- 不使用蓝紫霓虹、发光 AI 大脑、机器人装饰、玻璃拟态、强阴影或廉价科技海报效果。
- 不把 Redline 的文章 opening、长文正文、pull quote、图片图注等语义组件直接当作软件组件。
- 不用红色单独承担运行中、成功、警告、错误和解除设备等互相冲突的状态语义。

## 六、新旧版本切换合同方向

正式实施合同至少需要冻结以下机制：

- 托盘实例 ID、服务实例 ID、版本和构建标识。
- 仅本机可用的控制通道及其授权方式。
- 优雅停止、端口释放等待、启动新版和健康确认顺序。
- 新版启动失败时的回退与错误提示。
- 配对设备数据继续保存在 Windows 用户数据目录，升级不得清空。
- 未知进程占用端口时停止自动替换并提示用户。

## 七、当前状态与停止线

源码、托盘脚本、身份证明、五区 Redline 管理台和 Windows 便携包已作为实现候选落地。自动验证覆盖身份分类、设备改名/批量解除、管理台路由、样式隔离、构建、包清单、无 BOM 的跨运行时托盘状态文件，以及隔离 Headless 托盘 IPC（临时目录、随机非 8787 端口、ping/status/stop/start/同版本唤醒/换版释放 mutex）。重复扫码回归还覆盖了从手机扫码应用发起的顶层跳转：已有设备 cookie 使用 `SameSite=Lax`，再次扫码会刷新原设备 ID，不新增记录。

本机真实运行已证明：新目录托盘与服务替换后设备文件哈希保持不变；网页能读取真实托盘版本；五区导航、按需二维码、390px 无横向溢出、手机根入口扫码指引、二维码唯一授权、Tailscale 地址发现、关闭测试网页后后台继续运行和稳定后的同版本二次启动均通过。这里不把进程存在冒充为用户已经看到托盘图标。

尚未完成、因此不得写成交付通过的项：用户侧确认真实 NotifyIcon 可见与菜单操作、真实手机再次扫码不新增记录、未知占用 fail-closed 的人工对照、目标机解压便携包且无需额外 Node。
